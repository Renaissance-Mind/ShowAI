# ShowAI 技能与按需披露

ShowAI 插件提供三个工作流程。独立软件提供 CLI、阅读器、组件编译器和依赖；Agent 在第一次使用时读取启动配置并验证运行版本，之后沿用同一入口和内容目录。

| 技能             | 触发条件                                                 | 读取内容                                                                                  | 完成后                                 |
| ---------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------- |
| show-document    | 创建、修改、导出页面；应用已有模板                       | runtime 参考首次读；authoring/export 指南按操作读；所选组件或模板的 guide/schema/examples | 得到项目页面与交付物                   |
| create-component | 用户要求新组件，或既有数据调整和组件组合无法满足表达需求 | 组件设计参考；component 指南；选中组件的源码；子组件依赖                                  | 导入、在真实页面验证，再回到创作       |
| extract-template | 用户要求把已迭代好的页面抽象为模板                       | 模板抽象参考；template-extraction 指南；页面当前内容与差异；相似模板指南                  | 保存模板，应用不同材料验证，保留原页面 |

## 披露顺序

Agent 首先只见技能名称与描述，选择当前目标后读取该 skill。静态参考解决特定决策：运行入口、组件契约、模板抽象。CLI 返回当前软件支持的命令和实际内容库中的对象。

目录从 `catalog list --query 用途 --limit 8` 的摘要开始。选中对象再取 `--view guide`；准备输入时取 `schema`，参考用法时取 `examples`。普通页面创作不加载源码。开发或修改组件、合成模板时才使用 `source`，并按文件查询。版本合并、全局提升或发布在对应请求出现后读取 `versions` / `publish` 指南。

## 组件与模板的边界

组件封装表达和交互，输入由 schema 定义；模板封装内容组织与填写约定。页面中增加一张图可以直接应用已有组件。需要新的可复用交互时才开发组件。应用已有模板属于页面创作；提取模板是独立的用户目标。

提取模板保留成熟源页面，把实例事实和数据变成填写提示或空状态，保留有效结构与精确组件引用。contentGuide 说明每类内容的输入和证据要求。当前模板由 Agent 根据材料填充，尚无自动变量绑定机制。用不同内容应用一次，验证抽象没有泄漏原实例事实。

## 外部运行入口

桌面启动与 `runtime register` 都将启动配置登记到当前内容目录的 `agent-runtime.json`。技能使用其中的参数数组，调用 `runtime info` 校验协议、版本、目录及指南主题；软件路径变化时重新登记。单独修改或安装技能不重新构建运行软件。
