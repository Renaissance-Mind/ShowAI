# ShowAI 技能与按需披露

ShowAI 插件提供三个工作流程。独立软件提供 CLI、阅读器、组件编译器和依赖；Agent 在第一次使用时读取启动配置并验证运行版本，之后沿用同一入口和内容目录。

| 技能             | 触发条件                                                 | 读取内容                                                                                               | 完成后                             |
| ---------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------- |
| show-document    | 创建、修改、导出页面；应用已有模板                       | runtime 参考首次读；authoring/export 指南按操作读；所选组件或模板的 guide/schema/examples              | 得到项目页面与交付物               |
| create-component | 用户要求新组件，或既有数据调整和组件组合无法满足表达需求 | 组件设计参考；component 指南；选中组件的源码；子组件依赖                                               | 导入、在真实页面验证，再回到创作   |
| create-template  | 用户要求新建、修改模板，或从页面提炼模板                 | templates 指南与相似模板；按模式读取直接创建/模板抽象参考；提炼时读取 template-extraction 与源页面差异 | 保存可应用模板、使用提示与验证页面 |

## 披露顺序

Agent 首先只见技能名称与描述，选择当前目标后读取该 skill。静态参考解决特定决策：运行入口、组件契约、模板抽象。CLI 返回当前软件支持的命令和实际内容库中的对象。

目录从 `catalog list --query 用途 --limit 8` 的摘要开始。选中对象再取 `--view guide`；准备输入时取 `schema`，参考用法时取 `examples`。普通页面创作不加载源码。开发或修改组件、合成模板时才使用 `source`，并按文件查询。版本合并、全局提升或发布在对应请求出现后读取 `versions` / `publish` 指南。

## 组件与模板的边界

组件封装表达和交互，输入由 schema 定义；模板封装内容组织与填写约定。页面中增加一张图可以直接应用已有组件。需要新的可复用交互时才开发组件。应用已有模板属于页面创作；创建或修改可复用模板属于 create-template。

## 模板创建的两种方式

用户说“我想做一个项目周报模板”时，先结合已有对话明确读者、每次提供的材料、固定内容、可选内容与主要操作。用户明确指定方式就沿用；有具体材料、参考页面或需要看实际效果时先做页面再提炼；重复使用的结构已经明确时可直接创建模板。影响结构的缺项集中询问，其他信息在预览迭代中完善。

**先做页面再提炼**：用用户材料按 show-document 创建实例，展示阅读与交互效果，根据反馈迭代。已有成熟页面可以直接提炼。读取最新页面和差异，把实例事实与数据替换为填写提示或有效空状态，保留布局、阅读顺序与精确组件引用；保存模板后应用不同材料验证。原实例、模板和验证页面分别保留。

**直接创建模板**：按使用场景提供少量有实质差别的使用提示，例如周报可以选择“管理者速览”“团队执行”或“阶段复盘”。用户可以选择、组合或自由描述；需求充分明确时直接采用适合的方向。将选定的结构与填写约定写成模板定义，保存到项目，再应用为页面，填入用户材料并展示预览。材料缺失时先展示填写说明和空状态。

两种方式都保存 contentGuide，说明必需材料、组织方式、证据要求和可选条件；examples.request 保存可复制的使用提示，examples.steps 记录操作顺序。当前模板由 Agent 根据提示和材料填写页面。

预览后，用户可调整结构、必填项、可选区域与交互。通用结构反馈更新模板定义和预览，并保存新版本；本次内容反馈更新实例。明确反馈直接执行，范围无法判断时再询问。每次修改读取最新页面，纳入用户手动编辑。交付模板引用、使用提示和真实应用结果，后续反馈继续迭代同一模板。

## 外部运行入口

桌面启动与 `runtime register` 都将启动配置登记到当前内容目录的 `agent-runtime.json`。技能使用其中的参数数组，调用 `runtime info` 校验协议、版本、目录及指南主题；软件路径变化时重新登记。单独修改或安装技能不重新构建运行软件。

## 局部展示

`show-document` 根据本次需求选择展示范围。通过页面节点 ID 和 `export --blocks`，可以只导出一个组件、多个组件或区域，再把 inline 内容交给宿主的对话可视化通道。局部修改结果和自动化进度更新可以保留完整项目页面，只展示相关组件。具体命令按需读取 `guide export`；导出旁边的 JSON 同样只包含所选部分。
