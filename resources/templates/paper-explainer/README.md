# 论文讲解

读者要在不读原文的情况下正确理解一篇论文：它做了什么、为什么成立、证据够不够、边界在哪。这类讲解的共同困难是：论文按作者的写作顺序组织，读者却需要按理解顺序阅读；数字散落在口径不同的表里；机制藏在记号和框图后面；作者自己承认的限制写在最不显眼的地方。

四份指南分别教一种判断，而不是给出固定答案：

- intent：从请求与论文本身判断读者要用讲解做什么、已经会什么、会在哪里误读。
- material：把论文各部分读成带来源与条件的材料底稿，并按证据强度给论断分类。
- logic：从读者任务、论文的贡献结构与类型推出这篇论文自己的讲解顺序，再逐级展开。
- design：从"读者必须看出什么"推出每一部分的画面、交互与静态方式，再决定复用、扩展还是新建组件。

指南里标为"示例"的段落来自实际讲解页，用来说明按这些判断会得到什么；它们不是模板本身，另一篇论文按同样的判断会得到不同的结果。组件库是参考能力：模板附带组件库时 template_context 返回它们的精确引用，可以直接用或改数据，也可以扩展或按 create-component 新建；没有组件库时按设计指南用内置组件实现同样的画面。

没有材料的部分合并或省略，不为填满结构制造内容；页面上的每个数字都来自本次论文并带对照条件。
