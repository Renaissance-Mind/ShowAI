# 论文讲解

**产出什么。** 一页可交互讲解，让读者不读原文也能正确理解一篇论文：从任务背景与动机讲起，顺着论文的逻辑链条层层递进，每一部分只依赖前文已经讲过的内容，读者从上往下读不会遇到还没解释的结论、术语或数字；机制用稳定对象的状态变化讲，关键算法能亲手改参数看方向；每个数字在读者知道它怎么测之后出现，并只在同一口径内比较；作者承认的未验证项和讲解者发现的缺口显式可见；读者能自测是否读懂。

**整体路线。** 先从请求和论文本身判断读者要用讲解做什么、已经会什么、会在哪里误读（intent）；再逐节把论文读成带来源与条件的材料底稿，给论断按证据强度分类（material）；然后从检验任务、贡献结构和论文类型推出这篇论文自己的主干并逐级展开（logic）；最后为每一段从"读者必须看出什么"推出画面、交互与静态方式，再决定复用、扩展或新建组件（design）；按设计稿制作，对照读者简报与设计稿评审。

**示例：一篇方法论文得到的成品。** 任务背景（这类任务做什么、输入输出是什么，用论文自己的例子）→ 现有做法怎样处理、具体在哪一步不够（动机）→ 本文的思路 → 方法总览（对象在各阶段怎样更新、冻结、继承）→ 每个机制一节：要解决的难题、直觉、可拖的参数、公式与实际设置、没有被证明的部分 → 实验怎样测（数据、对照、指标）→ 同口径的主结果与按问题组织的消融 → 条件与局限 → 可信度账本 → 自测 → 来源。评测论文、理论论文按同样的判断会得到不同的主干，但都从背景与动机开始。

**指南、示例与组件。** 四份指南只教判断：看什么、怎样决定、为什么。标为"示例"的段落说明判断之后会得到什么，不是要照搬的结构。组件库是参考能力：模板附带时 template_context 返回精确引用，可直接用或改数据，也可扩展或按 create-component 新建；没有组件库时用内置组件实现同样的画面。

**边界。** 综述或多篇论文的横向比较、只要摘要翻译或逐段精读的请求不用这个模板。没有材料的部分合并或省略；每个数字都来自本次论文并带对照条件。
