# 论文讲解：呈现逻辑

这一阶段为这篇论文推出它自己的讲解顺序。顺序不来自论文的章节，而来自三个来源：读者简报里的检验任务、论文的贡献结构、论文的类型。下面的方法对任何论文都适用；标为"示例"的主干只是某些论文按这个方法得到的结果。

## 从读者简报推主干

把读者简报里的每个检验任务写在左边，右边写"哪一段讲解让读者能完成它"。没有任务对应的段落可以删，有任务没有段落就要补。再把论文的每条贡献（引言的列表，或自己归纳）对应到段落：贡献是机制的进机制段；贡献是结果的进证据段；贡献是资源（数据集、基准、工具）的要有"它是什么、怎样建的、能用来做什么"。证据段按主张组织，不按论文表格的顺序。

## 按论文类型选整体逻辑

先判断论文属于哪一类或哪几类的混合，再选起点逻辑：

| 论文类型         | 读者首先要知道                         | 常见主干形态                                                           |
| ---------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| 方法论文         | 它改了什么、为什么有效                 | 答案 → 问题 → 方法总览 → 机制 → 证据 → 条件与局限                      |
| 评测或数据集论文 | 它衡量什么、怎样衡量、现有方法表现如何 | 答案 → 要衡量的能力 → 构建方式与口径 → 评测结果与发现 → 局限           |
| 实证分析论文     | 它发现了什么规律、在什么范围成立       | 答案 → 问题与假设 → 实验设计 → 逐条发现 → 边界与反例                   |
| 理论论文         | 它证明了什么、依赖什么假设             | 答案 → 设定与假设 → 主要结果及直觉 → 证明思路 → 与实验或已知结果的关系 |
| 系统论文         | 它解决什么工程问题、代价是什么         | 答案 → 需求与约束 → 架构与关键决策 → 性能与代价 → 适用场景             |

混合类型按主贡献选起点，其他贡献作为分支。表中的形态是起点，不是终点；下面的原则会继续调整它。

## 组织原则及其理由

每条原则解决一种读者困难；某篇论文没有相应困难时，对应段落不设。

- 答案先行：读者在任何深度停下都得到正确图景。首段给结论、关键数及其条件、最重要的限制。
- 先问题后方案：先用论文自己的例子说明现有做法为什么不行，读者才知道每个设计为何存在。
- 机制用稳定对象的状态变化讲：框图里的抽象名词无法让读者预测结果；列出参与对象，按步骤说每个对象改变了什么、保留了什么。
- 关键算法让读者操作：能改一个参数看结果方向的机制，读者才算理解；只在论文给了明确规则时设计操作。
- 每个数字带条件：没有对照对象与口径的数字会被误读；数字在哪里出现，条件就在哪里可见。
- 消融按问题组织：每组消融回答"不这样会怎样"，比表格更容易读。
- 局限显式可见：作者承认的未验证项与讲解者发现的缺口放在主线，不折叠。

## 可选环节的加入条件

| 环节                   | 加入条件                                                   |
| ---------------------- | ---------------------------------------------------------- |
| 术语速查               | 正文反复出现的缩写或记号超过五六个                         |
| 训练配方               | 读者要复现，且论文给了完整设置                             |
| 按难度或子集分层       | 论文按难度、长度或域分层报告，且分层改变结论               |
| 训练动态与被舍弃的分支 | 论文展示了非单调的训练曲线或被放弃的变体，影响对结果的信任 |
| 校准或置信度           | 论文的输出带概率，且被当作可信号使用                       |
| 适合与不适合判断表     | 读者要决定是否采用                                         |
| 自测                   | 讲解较长或读者要转述；题目对应检验任务                     |
| 延伸阅读               | 论文的差异点依赖前作                                       |

## 第二级怎样展开

对每个环节问它该回答的问题，答案就是它要讲清的内容：

- 首屏：一句话主张是什么；哪三四个数字最能代表它，各自的对照对象与口径；最重要的一条限制；熟悉主题的读者可以从哪里直接进入。
- 问题段：贯穿例子是什么；现有做法对它怎样处理；成本或误差具体来自哪一步，有没有数字。
- 总览段：参与的稳定对象有哪些；每个阶段或步骤对各对象做了什么；阶段之间传递了什么。
- 机制段（每个机制一节）：一句结论；直觉；可操作的参数与预测方向；公式及记号含义；实验实际启用的设置；没有被证明的部分。
- 证据段：每张表的口径；本文相对对照的差值与倍数；哪一步贡献最大；分层或案例揭示的失败形态；每组消融回答什么。
- 条件与局限段：读数字前必须知道的条件（怎样算、怎样采样、基线怎样跑、什么没算）；作者承认或可从实验看出的边界。
- 可信度段：每条主要论断属于哪种证据类型，证据摘要与位置。

叶子写具体的定义、过程、例子或条件，并给可观察的 check（"给出阶段名，读者能说出各对象的状态""拖大阈值，读者能预测区间变窄"）。先备关系用 needs 标出：机制依赖贯穿例子与基础角色，证据依赖口径，自测依赖前面的主干。读者能完成对应任务时停止展开，各分支深度可以不同。

## 示例：两篇方法论文得到的不同主干

一篇用候选打分替代自回归生成来做视频判断的论文：首屏 → 问题（贯穿例子、生成为什么慢）→ 机制（打分头、从分数解码区间与选项、两种复用模式）→ 训练配方 → 证据（定位、问答、消融、问题数扩展、校准）→ 口径 → 案例 → 局限与适用判断 → 来源。校准与案例因为论文有相应材料且影响"能不能用"才加入；没有术语速查，因为新缩写不多。

一篇递归自改进终端 agent 训练的论文：首屏 → 术语速查（缩写密集）→ 五阶段总览（对象在阶段间的更新、冻结、继承）→ 三个难题与三个对策 → 机制细看（每个对策一节，含可操作图）→ 结果（各阶段、同行位置、难度分层、训练动态、案例）→ 可信度 → 自测 → 来源。难题与对策段因为方法由三个独立组件构成才出现；训练动态因为论文展示了被舍弃的分支才加入。

两篇都是方法论文，主干仍不同；差异全部来自上面的判断，而不是来自模板。
