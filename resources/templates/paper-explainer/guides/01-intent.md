# 论文讲解：理解意图

这一阶段判断三件事：这位读者拿讲解去做什么；读这篇论文前已经会什么、必须先补什么；这篇论文最容易在哪里被误读。结论写成读者简报，后面三个阶段都以它取舍。

## 从请求推断深层需求

用户给论文时的表面要求几乎都是"讲解这篇论文"。深层需求从三条线索判断：谁在问（研究者、工程师、学生、评审）、为什么现在问（刚看到、要复现、要在组会讲、要判断一条宣传说法）、拿到讲解后要做什么。判断后写成一句"读者要用这份讲解去……"，并据此决定重心往哪里移、哪些部分可以减轻：

| 用途（示例）           | 重心移向                                         | 可以减轻的部分 |
| ---------------------- | ------------------------------------------------ | -------------- |
| 决定要不要细读或复现   | 主张、证据强度、复现条件、局限                   | 机制推导细节   |
| 把方法迁移到自己的问题 | 机制细节、每个组件解决的难题、参数直觉、适用边界 | 同行排名       |
| 在组会或文章里转述     | 一句话主张、关键数字的对照对象、口径陷阱、可信度 | 训练配方       |
| 核验一条宣传式说法     | 论断与证据的对应、作者承认未验证的部分           | 术语与背景     |

表中是常见用途，不是全部；遇到新的用途按同样方式写出重心与可减轻的部分。没有线索时按"决定是否细读并能正确转述"推进，并在读者简报中注明这一假设。

## 从论文本身判断读者认知起点

读者描述常常只有一句话（"有 ML 基础"），更可靠的依据是论文自己：

- 相关工作与引言里不加解释直接使用的概念，是论文默认读者已经会的；若目标读者比论文的默认读者更外行，这些就是要补的第一批概念。
- 记号定义、方法节首次出现的术语、作者自造的名字，是论文新引入的；所有读者都要在讲解中得到定义。
- 评测节里评测怎样判定成功、指标怎样计算，常被论文一笔带过，但读结果前必须先懂；列为"必须先补"。

由此得到两张清单：可以直接使用的概念；必须先补的概念及其在讲解中的位置。

## 判断这篇论文容易产生的误解

误解来自论文的结构，不来自读者的粗心。逐项检查论文是否有这些结构；有就预计读者会误读，并决定在哪里澄清：

- 多套评测口径并存（不同推理模式、评测次数、子集）→ 读者会把不同口径的数字当成同一比较。
- 既有重新评测的基线也有沿用已发表的分数 → 读者会把参考值当成同协议对照。
- 既有训练结果也有离线重算或推导 → 读者会把重算或推导当成训练效果。
- 作者在局限、附录或脚注承认未验证 → 读者会把这些当成已证明。
- 方法由多个组件构成但消融不完整 → 读者会把整体提升归功于某个组件。

只有会影响主线判断的误解才提前澄清；其余在相应位置顺带说明。

## 写可检验目标

目标只写读者看完能做什么。从论文的主要主张逐条推出检验任务：每条主张至少对应一个读者能完成的复述、判断或预测；每个预计的误解对应一个判断题。任务数量由主张数量决定，不是固定清单。

示例：一篇"用候选打分替代自回归生成来做视频判断"的论文，主张"更快"推出"说出加速倍数的对照对象与推理模式"；主张"更准"推出"说出主结果表的口径与本文行相对骨干的差值"；机制主张推出"预测阈值变大时区间怎样变化"；作者承认的未校准推出"判断置信度能否直接当概率用"。

## 材料入口与环境

记录论文编号、版本、日期、页数、原文链接与本次讲解的截止日期。环境沿系统默认（电脑全屏、可交互）；用户要求静态导出或窄屏时，在设计阶段为每幕写相应方式。只有读者群体明显不同或用户限定篇幅时才先询问，其余按假设推进并注明。
