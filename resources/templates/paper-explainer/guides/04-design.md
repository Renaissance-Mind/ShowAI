# 论文讲解：呈现设计稿

这一阶段为呈现逻辑的每个环节设计画面。方法是从"读者必须看出什么"出发，推出对象与空间关系、交互、静态与窄屏方式，最后才决定用什么组件。标为"示例"的部分来自实际讲解页，说明推导之后会得到什么。

## 整体布局怎样定

- 开篇就是背景与动机的第一幕：用论文自己的贯穿例子或一幅示意说明任务的输入与输出、现有做法怎样处理、在哪一步不够，读者看完知道这篇讲解从什么问题讲起。开篇不放全文总结、结论卡、关键数字卡或"本页结构"清单，读者此时还不知道方法与测法，看不懂它们。不重复 Page 标题。
- 阅读流按呈现规划的顺序，读者从上往下读时每一幕只依赖前面的幕。每个图形前一段导语（接下来看什么、用哪个例子、怎样操作），后面按需一段读图要点（看完应能回答什么）；长章节拆成图文相邻的片段。
- 角色色：为论文的稳定对象（模型角色、数据、片段、候选……）各分配一种颜色，全页所有图形与正文中的对象名沿用同一颜色。
- 论文原图：论文正文的每张图都放进讲解，位置在讲解它内容的那一幕，读者在读到相应论述时就能对照原图。多面板图按面板拆开，方法面板跟随方法段，结果面板跟随讲完测法之后的证据段。为某个机制做的可交互重绘与原图相邻，原图给出论文的完整画面，重绘让读者亲手操作。每张原图或拆出的每个面板用一个 image 块完整展示，保留该面板的图例与标签，宽度按长宽比设定；图注写清图号、画了什么、读者应从中看出什么。附录图在支撑关键判断时加入。
- 悬停注释：缩写、记号、专有名词和公式变量在出现处加注释（呈现逻辑里已标出哪些实体用注释）。正文、表格、组件标题与说明、图表标签写 `[可见文字]{注释}`；公式里写 `\note{变量}{注释}`，可以只注释一个变量，也可以在同一公式里注释多个；`[$公式$]{注释}` 注释整个公式。注释用一两句话写清它是什么、形状或单位、在论文中的取值或出处，可以含 `$…$` 公式。带注释的文字自动显示虚线下划线，读者悬停、键盘聚焦或在触屏上轻点时出现气泡。
- 文字模式：每一节先交代它要回答的问题，再讲做法、直觉与证据，最后一句点明这一节得到了什么，不在节首先抛结论。每条论断的证据类型与成立条件写在它出现的位置；保留意见放进以固定短语为标题的提示框（"没有被证明的部分""实验上的限制""讲解者补充"），紧跟它所限定的结果。这样读者在读到每个结论时就能区分论文说的、证据证明的和讲解者加的。

## 文字样式

正文用一套固定的文字样式引导注意力。写正文前先定下样式表，每种样式只表达一种含义，全文一致，读者读过两三节就能凭样式认出信息的类别：

| 含义                                   | 样式                                     | 示例                                   |
| -------------------------------------- | ---------------------------------------- | -------------------------------------- |
| 论文的稳定对象（模型角色、组件、数据） | 粗体，文字颜色取该对象的角色色           | 正文里的 Main、Subagent 与图中同色     |
| 每节要回答的问题                       | 节首一句，整行淡色底（highlight 的 mode 取 full） | 这一节回答第二个难题：……               |
| 核心概念的定义处                       | 粗体加下划线，只在定义出现的那一次       | 任务复杂度、证据契约                   |
| 读者要对照的数字                       | 黄色高亮加粗体                           | 均分从 33.19 升到 42.95                |
| 改变结论或读数的陷阱                   | 红色粗体                                 | 四者使用同一个底座模型；两处口径不同   |
| 本节得到的结论                         | 粗体                                     | 大部分领先与落后都在 2 分以内          |
| 缩写、记号、专有名词                   | 悬停注释                                 | Elo、BM25、决策边界                    |
| 实验限制、未证明部分、讲解者补充       | 提示框（callout），标题即固定短语       | 浅橙底：实验上的限制、没有被证明的部分；浅灰底：讲解者补充 |

样式用在读者需要停下来的地方，一段里通常两三处，同一处文字只套用样式表中的一行。颜色、高亮和下划线没有 Markdown 写法：先用 Markdown 写好正文，再用 `block.replace` 给需要样式的文字加 marks（`textStyle` 的 `color`、`highlight` 的 `color` 与 `mode`、`underline`、`bold`），结构见 text 组件 guide 的“结构化富文本与局部格式”。表格单元格与公式旁的文字同样适用。

## 按读者要看出的东西推画面

| 读者必须看出                         | 用什么表达                                                                   | 需要什么交互                                   | 静态与窄屏保留什么               |
| ------------------------------------ | ---------------------------------------------------------------------------- | ---------------------------------------------- | -------------------------------- |
| 现有做法与本文做法处理同一输入的差异 | 同一输入并排两条处理路径，差异处用颜色与标签标出                             | 点击一段看它的作用，其他降饱和                 | 两条路径都显示；窄屏改为上下排列 |
| 对象在阶段间怎样更新、冻结、继承     | 阶段 × 对象的矩阵，每格一个状态词，继承用虚线穿过；底部一行逐阶段指标        | 点击阶段看这一步做了什么；点击对象追踪它的传承 | 整个矩阵；窄屏横向滚动并固定首列 |
| 每个设计解决哪个难题                 | 左难题右对策的编号配对，中间连线                                             | 点击一对展开"为什么能解决"与证据强度           | 全部配对各带一句理由             |
| 一个机制逐步发生了什么               | 同一组对象的连续帧，每帧标出改变、承接、固定                                 | 上一步 / 下一步、回到起点、展开全部            | 展开全部帧                       |
| 改变参数后结果往哪个方向走           | 参数可拖，读数与选中结果实时变化，默认值等于论文设定                         | 拖动、重置                                     | 默认状态加两个关键取值的对照     |
| 在同一口径下读结果                   | 本文行高亮，其下直接显示相对对照的差值与倍数；每列最优加粗；口径在表头或脚注 | 按组筛选、只看对照                             | 完整表                           |
| 本文在同行中的位置                   | 按数值排序的条形与名次，本文高亮，参考值标明来源                             | 切换基准                                       | 当前基准一组                     |
| 一组消融各说明什么                   | 每组一张卡：问题 → 基线 vs 改动 → 差值条 → 结论                              | 展开细节与表号                                 | 全部卡片                         |
| 多个系统处理同一组任务的交付物差异   | 论文的对比原图完整展示；表格每行一类任务，列出作者观察到的差异与作者自述的限制 | 无                                             | 原图与表格                       |
| 一个结果的证据强度与条件             | 结果旁一句写明证据类型与条件；保留意见用紧跟其后的提示框                     | 无                                             | 正文与提示框                     |
| 公式里每个符号的含义                 | 在公式中用 `\note{变量}{含义}` 为每个变量加注释，带注释的部分显示虚线下划线 | 悬停、键盘聚焦或轻点变量显示注释              | 公式下方一行列出变量与含义       |
| 论文原图的内容                       | 原图完整展示在讲解它的那一幕，图注说明要看出什么；必要时旁边配可交互重绘     | 重绘部分按其机制设计                           | 原图与图注                       |

遇到表中没有的任务，按同样顺序推：先写读者必须看出什么，再写对象与关系，再写交互与恢复，最后写静态方式。

## 怎样决定用什么组件

顺序：调整已有组件的数据与布局 → 组合已有能力 → 扩展已有组件 → 为确认的缺口新建组件。判断标准是上表"用什么表达"一栏能否被现有组件原样实现：能，就填数据；差一个字段或一种视图，扩展；画面结构不同（例如论文特有的解码规则、信用衰减链、通道间的可访问性差距），新建。新建时为 create-component 写清输入与输出、视觉语义、读者操作、状态归属、空态与错误态、窄屏与静态方式、通过条件；对象与颜色沿用本页角色色。

## 每幕要求

开篇从背景与动机起，不出现读者尚未能理解的结论与数字；每个数字出现前，它的测法已经讲过；公式中的变量都带注释；论文正文的每张图都已分配到一幕；正文按样式表标记；机制幕保持同一组对象身份与角色色，默认状态即论文设定，交互只改变阅读焦点并写清恢复方式；证据幕只在同一口径内比较，差异写在脚注或行说明，参考值标明来源；示意数据在组件说明字段标明并在来源节重申；每幕写 static 与 narrow；制作后记录真实 blockIds。

## 示例：两幕设计稿

阶段 × 对象矩阵（一篇递归自改进训练论文的总览）。读者要看出：五个阶段里 actor 每步都在变，critic 只在强化阶段训练、在改写阶段原样穿过。composition：横向五列阶段（RSR-1、RPR-1、RSR-2、RPR-2、最终），纵向三行对象（actor 蓝、critic 紫、奖励函数橙）；每格写"更新 / 冻结 / 继承 / 准备"，继承格用虚线横穿；底部一行写各阶段的严格成功率均值。interaction：点击阶段列高亮该列并在下方显示这一步做了什么；点击行名高亮该对象的传承线；Esc 恢复。text：导语说明"两种动作交替两轮，critic 接力不重置"；读图要点三条（哪个对象从头到尾不变、第一轮强化增量最大、学习方式一行的注意标记）。static：完整矩阵与指标行。narrow：横向滚动并固定首列。check：给出阶段名，读者能说出各对象的状态。

可拖参数（一篇把候选分数解码成时间区间的论文）。读者要看出：阈值变大时区间变窄；略低于阈值的候选会被两侧高分候选"架过去"。composition：时间轴上每个候选一根柱，高度为概率，标注区间作底带；τ 水平线可拖；被选的连续段高亮；右侧读出预测区间与 IoU。interaction：拖 τ 实时重算；重置回论文设定。text：导语"先猜再拖动验证"；图注说明分数为论文图的示意值。static：论文设定与一个较大 τ 的两帧对照。narrow：轴与读数上下排列。check：读者能预测 τ 变大后区间的变化方向。
