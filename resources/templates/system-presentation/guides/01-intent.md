# 系统呈现规则：理解意图

这一阶段回答一个问题：读者实际想知道什么，以及要让读者理解它，先得补上什么。产出一份读者简报，后面三个阶段都以它为依据。

## 判断真实需求

用户的提问或指令可能片面、不完整。先把表面要求写下来，再结合对话上下文、材料和任务场景推断深层需求，并说明依据。两者不一致时按深层需求组织内容，但把用户明确问到的内容放在显眼位置回答。

| 项目         | 写什么                                                 |
| ------------ | ------------------------------------------------------ |
| 表面要求     | 用户的原话要求什么形式、什么范围                       |
| 深层需求     | 读者拿到内容后要做什么判断、决定或操作；为什么现在需要 |
| 本次回答范围 | 必须覆盖什么；可以不讲什么；推断出来的部分标为假设     |

只有题目时按最合理的读者与用途假设推进，并在简报中注明假设。只有当不同理解会导致完全不同的作品时才向用户提问；其余用假设继续。

## 判断读者认知

| 项目       | 写什么                                                   |
| ---------- | -------------------------------------------------------- |
| 读者是谁   | 身份、领域背景、阅读目的                                 |
| 已经理解的 | 可以直接使用、不必解释的概念与事实                       |
| 缺少的知识 | 理解结论前必须补上的概念、关系或背景；每项注明在哪一步补 |
| 可能的误解 | 常见误读，以及它是否会影响后面的理解                     |

会影响后续理解的误解先澄清：先解释相关概念、给出可核实的例子或反例，再展开原来的问题。不影响主线的误解在相应位置顺带说明即可。

## 任务结果与环境

写出读者看完后能够解释、判断或完成的事情，并给出检验方式，例如“能说出 A 为什么比 B 快，并指出前提条件”。这些检验在呈现逻辑阶段变成各部分的通过条件，在评审阶段逐项核对。

记录环境与约束：设备与实际视口、是否可交互、是否要导出静态或打印版本、阅读时间预算、用户指定的素材、模板、格式与保存归属。没有特殊要求时按电脑全屏、可交互阅读设计。

## 读者简报

把以上内容合成一份简短的读者简报（对话中可以是几行，复杂作品保存为规划记录的 reader、startingKnowledge、goal、environment 字段）。简报满足三点即可进入下一阶段：目标可检验；影响结果的未知条件已处理或标明；知道要先澄清哪些误解。
