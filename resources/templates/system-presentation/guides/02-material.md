# 系统呈现规则：收集与处理材料

这一阶段为呈现准备可靠的内容基础。根据场景确定需要哪些原始信息、从哪里取得、怎样核对和整理。产出材料底稿；后面的呈现逻辑只使用底稿中有依据的内容。

## 何时可以省略

场景通用、没有统一的原始信息来源和处理方式（例如解释一个常识性概念、整理用户已经给出的完整材料），这一阶段可以省略，直接进入呈现逻辑。省略时仍对要用到的事实做一次来源与条件检查。

模板可以为特定场景规定采集清单与核对方式（论文讲解核对表号与评测口径，数据分析核对粒度与单位，教程核对真实入口与版本）。有模板指南时按其清单执行。

## 确定需要什么

从读者简报倒推：读者要作出的每个判断需要哪些事实、数字、例子、图像或原文；每个要澄清的误解需要哪个反例或定义。列成清单，再决定来源：用户提供的材料、原始文献或数据、官方文档、检索结果、真实截图。优先原始来源，不依赖二手摘要。

## 核对与整理

材料底稿按条目记录，每条包含：

| 字段 | 内容 |
| --- | --- |
| 主张或数据 | 原文或原值，不改写 |
| 来源定位 | 文件、页码、表号、图号、链接或命令输出 |
| 条件 | 成立的前提、口径、单位、样本、日期、对照对象 |
| 性质 | 事实、作者主张、他人评价、分析推断、设计建议、生成示意 |
| 用途 | 将支持哪个结论或解释哪个概念 |

材料之间冲突时记录口径与条件差异，不用平均或多数票消除。不同口径的数字不并列比较。缺少决定性材料时继续查找或缩小结论范围；不为填满结构编造数据或例子。

需要图片时记录真实素材的来源与版权状态；准备用图像生成制作示意图的，先写下必须保持准确的对象、数量、关系与标签。

## 停止条件

材料足以回答读者的主要问题、支撑关键判断并说明重要限制时停止。时间范围延伸到当下的主题以实际检索日为界，单独说明已公开的后续计划。把真实缺口写进底稿，它们会成为成品中明确的限制，而不是被省略的部分。
