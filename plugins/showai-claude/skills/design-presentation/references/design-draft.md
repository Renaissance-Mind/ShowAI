# 设计稿

设计稿把呈现规划变成具体画面，是制作的唯一依据。它描述画面中有什么、怎样组织、彼此关系，详细程度接近图像生成的文本指令；另一位制作者应能据此画出或实现同一画面。

## 环境与排版

默认电脑全屏可交互阅读，1440×900 CSS 像素为参考视口；实际宿主视口决定布局。示意图或演示画面可用 16:9，长文自然纵向排布。窄视口重排图文和导航，必要的二维表图提供明确的滚动与总览方式。

桌面正文 18–20 px 起，图注和标签按渲染尺寸检查；空间不足时改结构或拆分，不依赖极小字号。固定字体体系，用留白、对齐、间距和语义分组组织内容；标题直述主题；重点的样式与含义一致。必要图形提供文字替代，颜色不单独传递信息；检查对比、键盘焦点、放大与重排。

## 整体布局

- 首屏在参考视口内不滚动就能让读者明白这份内容从什么问题讲起、范围是什么，并看到一幅可理解的画面；读者需要先了解背景时，首屏就是背景与动机的第一幕，不放读者此时看不懂的结论或总览。不重复 Page 标题。
- 图文相邻：说明放在它解释的图形旁；不先铺多段背景再放一张图，也不先写完整长文再给各章附一张概括图。
- 节奏：长章节按理解节点拆成图文相邻的片段，避免一两个交互区后接几大块连续正文。
- 对象身份：同一对象在全页使用同一名称、颜色与形状；颜色与文字、形状或线型共同表达状态。

## 依据读者任务选择表达

| 读者任务 | 主要表达 | 说明与交互 |
| --- | --- | --- |
| 认识对象与组成 | 原图、截图、剖面或标注示意 | 定义关键对象，选择局部时就近解释 |
| 理解步骤与状态变化 | 流程、连续分镜、前后状态 | 说明触发条件，保持对象身份 |
| 理解机制 | 输入—作用—结果关系；可操作参数 | 说明依据、假设和适用边界；读者能预测变化方向 |
| 比较与取舍 | 对照表、同尺度小多图、决策路径 | 共同口径，缺项可识别，建议带条件 |
| 趋势、分布与异常 | 与数据语义匹配的图表 | 单位、样本、日期、原始值及来源 |
| 完成操作与排错 | 真实界面标注、步骤与分支 | 动作、预期反馈和恢复方式 |
| 探索与系统理解 | 总览与可定位局部 | 放大、筛选、详情及返回总览 |
| 核对论证或精确规定 | 有层次的正文、公式和原文 | 突出条件，图文相邻，来源可定位 |

每张主图应明确读者要从中发现什么。图形的方向、空间、连接和尺度承担语义；文字补充定义、条件与推理。装饰不能制造未经证据支持的因果、比例或排名。几个抽象名词放进框中不构成机制解释；证据条目不能代替需要展开的机制。

## 文字与强调

文字承担必要的辅助解释：导语说明接下来看什么、用哪个例子、怎样操作；图注解释图中未讲清的概念与细节；要点说明看完应能回答什么；正文承担精确论证时说明必要性。信息完整、准确、无歧义。加粗标出结论与关键条件，颜色按角色或状态固定，同类含义同一样式；不用样式制造没有依据的强调。

公式中的变量与记号、缩写、专有名词和特定用词，用悬停注释给出一两句解释：读者悬停、键盘聚焦或在触屏上轻点带虚线下划线的部分时显示气泡。正文、表格、组件标题与说明、图表标签写 `[可见文字]{注释}`；公式里写 `\note{变量}{注释}`，一个公式可注释多个变量；`[$公式$]{注释}` 注释整个公式。注释写清它是什么、形状或单位、取值或出处，可含 `$…$`。设计稿在相应幕的 text 中列出要加注释的实体与注释内容；主线必需的定义和改变结论的条件写在正文。静态导出不显示气泡，变量多的公式在下方补一行变量说明。

## 交互

明确初始状态、触发动作、状态变化、可见反馈、恢复方式、键盘和窄屏行为。默认状态是材料中的真实设定。阅读中的选择、筛选、缩放和临时参数属于阅读状态；更改事实或持久默认值需要正式保存。空数据、错误、加载与缺少来源都显示真实状态。重要条件不能只放在悬停说明里。

静态交付保留主线、重要条件和来源：逐步交互转为关键状态的连续分镜；计算探索保留公式、范围、选定条件与结果。导出 HTML 可交互，不自动等于纸面或图片版本已经完整。

## 图像

图片可来自真实素材或图像生成。生成前确定对象、关系、标签、构图和不应改变的事实；生成后检查文字、箭头、数量、比例暗示与遮挡，出现自动补出的数据或主张时修订。正文、精确数据和要交互的对象保持原生可编辑。保留采用的图片、提示词及必要修改记录，标明生成示意与真实素材。

## 保存设计稿

在规划记录的 scenes 中逐幕记录。校验脚本要求每幕具备 id、nodes、form、composition、visualReason、static、narrow、check；text、interaction、assets 按需填写，blockIds 在制作后补：

| 字段 | 内容 |
| --- | --- |
| id、nodes | 场景标识；它解释的规划节点 id |
| form | 表达形式与所选组件或原生区块 |
| composition | 对象、相对位置、箭头或尺度、准确标签、颜色、阅读顺序与文字落点 |
| visualReason | 为什么这种表达能支持当前任务 |
| text | 导语、图注与要点各写什么；哪些词加粗或着色 |
| interaction | trigger、change、reset；没有交互时省略 |
| static、narrow | 静态导出显示什么；窄于 640 px 时怎样重排 |
| assets | 真实素材来源，或图像生成提示与核对要点 |
| check | 读者看完这一幕应能完成的复述、判断或操作 |
| blockIds | 制作后填入：源页面中实现该幕的真实节点 ID |

示例：暖白底，标题“同一个问题，两种输入布局”。上行是生成式模型的序列：[视频][问题] 后接逐个生成的时间 token，灰色箭头表示逐步输出；下行是打分式模型：[视频][指令+问题][候选…][decide]，候选段橙色，共享的视频段标“共享”。点击任一片段时下方说明区显示该片段的作用，其他片段降低饱和度；再次点击恢复。图注解释“共享”意味着只计算一次。窄屏时两行改为上下堆叠并允许横向滚动。

“文字加关系图”“白底简洁”不能单独成为 composition。分镜中的对象使用本篇的真实名称；多个可能对象的并列占位不能代替选择。设计因证据或版式改变时保留原记录再修订当前记录；不把未实现的画面记为完成。

## 用真实内容检查密度

在目标视口估计标题、说明、控件和主图共同占用的空间。首屏让开篇的问题与画面可辨认；长定义、背景和方法放到它所解释的图形附近或后续段落。每个主要理解任务都要有具体的表达落点；逐项检查读者如何从图形或示例看出变化、因果、条件和差异。
