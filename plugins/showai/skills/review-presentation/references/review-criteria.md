# 呈现评审标准

从任务简报反推验收。每个主要理解节点对应一个可观察的复述、判断或操作。实际测试范围与工具能力、用户约束和交付环境一致。

| 维度       | 检查                                           | 失败后的修改方向           |
| ---------- | ---------------------------------------------- | -------------------------- |
| 事实与证据 | 主张性质、来源定位、数据、单位、日期和条件一致 | 修正材料、计算或主张范围   |
| 理解主线   | 核心关系可复述，先备概念有解释，关键条件可见   | 调整认知起点和多级规划     |
| 迁移判断   | 新例子中能按同一原则判断，并知道适用边界       | 增加具体例子、反例或边界   |
| 视觉可读性 | 实际视口中标题、标签、图例与说明清楚；编码一致 | 修改布局、密度、字号与编码 |
| 交互恢复   | 操作有明确反馈，可回到总览；键盘与窄屏可用     | 修正触发、状态和恢复路径   |
| 交付续改   | 源页面、素材、依赖与回执齐全；静态含义保留     | 修正保存、导出与兼容处理   |

## 问题记录

写清具体位置与条件、实际观察、读者影响和建议，不仅写“太复杂”或“不够直观”。严重问题包括错误事实、缺少决定性证据、条件被隐藏、无法完成主要操作。其他问题按影响和修复范围排序，不用总分抵消严重缺陷。

检查生成图中的准确标签、连线、数量和比例暗示。检查模板是否仍残留填充提示、旧实例事实或无关空章节；真实缺项应是成品中的清楚限制。只读页面不出现正式编辑控件，阅读操作不改写源内容。

## 证据层级

源数据核对能证明结构与数值；截图能证明捕获视图；实际操作能证明该路径的行为；目标读者试读才提供理解效果证据。工具成功、编译成功与用户实际看见结果分别确认。遵循宿主官方电脑操控规则，不把自动化脚本等同于规定的界面验收。

浏览器或渲染能力不可用时完成可做的内容检查，保留明确未验证项；不要换不被允许的操控路径。静态版本检查所选状态、主线、条件、来源及必要附表，不以交互版截图替代所有静态任务。

## 读者试读

根据目标选择任务，例如解释一个关系、在新条件下作选择、找到某条主张的来源、指出限制或完成一个操作。记录错误、遗漏、定位路径、停顿及理由。不要用阅读时间或偏好单独代表理解。

比较版本时保持材料和任务可比，考虑阅读顺序与学习效应。少量试读用于发现问题，不能直接推断总体效果；定量结论需要另行设计样本和分析。未执行时交付测试方案及预期观察，不填写虚构结果。
