模板保存可复用的内容结构、组件组合和填写约定。用户要求创建模板时，交付可应用的模板、使用提示与验证页面。

沿用已验证的外部 CLI 与用户选定的项目；首次使用读取 [运行入口](../show-document/references/runtime.md)，按其中约定定位或创建项目。读取 `guide templates --json`，按用途查询 `catalog list --kind template --project PROJECT --query 用途 --limit 8 --json`，选中后读取 guide/examples；复用、修改或合成定义时才读取所选源码。已有模板可作为基础；说明新增结构或填写约定的用途。

## 选择创建方式

- **先做页面再提炼**：用户提供现有页面、具体材料或视觉参考，需要通过实际内容确定布局与交互。读取 [模板抽象](references/template-abstraction.md)，按 [show-document](../show-document/SKILL.md) 创建或迭代实例，然后回到本技能提炼；已有成熟页面可直接提炼。
- **直接创建模板**：用户已能说明重复使用的场景、内容结构或填写需求，或明确要求直接新增模板。读取 [直接创建与互动](references/template-creation.md)，提供可选使用提示，建立模板定义，再应用为预览页面。

用户已指定方式就沿用；否则根据材料与结构的明确程度选择，并简短说明。只有选择会明显影响结果且无法推断时，询问“先做一页看效果再提炼”或“直接建模板再看应用效果”。两种方式可在迭代中切换，复用已经形成的页面或模板。

## 与用户迭代

从现有对话提取用途、读者、重复填写的材料与预期阅读或操作结果。只询问影响结构的缺项，例如“每次会提供哪些材料”或“读者最需要比较什么”；用户目标充分明确时直接创作。根据用户的具体场景提供少量有区别的方向或使用提示，允许选择、组合或自由描述，选择方向后开始制作。

展示实际页面或模板应用预览，让用户围绕结构、内容必填项、可选区块与主要交互提出修改。模板任务中的结构调整同时更新模板定义与预览；本次数据或措辞调整只影响实例。范围无法推断时再询问。提炼前或改动预览前重新读取页面当前内容与 hash，纳入用户手动修改。反馈充分明确时继续完成修改与验证；无需每一步等待确认。

## 保存与交付

生成当前 CLI 支持的 document/composition 定义，将实例事实替换为填写提示或 schema 有效的空状态，保留布局、阅读顺序与精确组件引用。contentGuide 记录各区域的必需材料、组织方式、证据要求和可选条件；scenarios 说明适用场景，related 说明依赖用途，examples 保存命名的自然语言使用提示与操作顺序。提示由 Agent 根据材料执行。

用 `template save --project PROJECT --input template-definition.json --json` 保存到当前项目；修改已有模板使用新版本。用 `template apply` 创建验证页面，按所选提示填入材料，再检查阅读效果、主要交互和导出。直接创建也要完成应用验证；从实例提炼时使用不同材料检查复用。材料不足时使用填写提示与空状态展示结构，说明内容验证仍待材料补齐。

交付模板名称、适用场景、精确版本与指纹、可复制的使用提示，以及预览或导出结果。原实例与验证页面分别保留。后续反馈延续同一模板并创建新版本；用户要求共享或发布时再读取对应指南。
