# 直接创建模板与使用提示

直接创建适合已经明确重复使用场景的请求，例如“我想做一个每周汇报项目进度的模板”。先从需求中明确读者、每次输入的材料、固定内容、可选内容与主要操作。将影响结果的缺项集中问一次；已有信息够用时按合理结构创建，并在预览中说明可调整之处。

## 提供可选方向

方向用可复制的自然语言使用提示表达，让用户能判断实际用途。结构尚未明确时提供两到三个有实质差别的选择；已明确结构时直接给出该结构的使用提示。不要把颜色或名称的变化当作不同模板方向，也不要要求用户理解 JSON 或组件 API。

例如用户要项目周报模板，可以提供：

- **管理者速览**：“用这份项目周报模板，基于我提供的进度、里程碑和风险材料，先展示本周变化，再列出需要决策的事项；缺少的数据标为待补充。”
- **团队执行**：“用这份项目周报模板，按任务、负责人、截止时间和依赖组织进展，突出阻塞事项，并支持按状态筛选。”
- **阶段复盘**：“用这份项目周报模板，对照本阶段目标和实际结果，整理偏差、依据与下阶段行动；没有证据的原因标为待核实。”

提示是用于选择和应用模板的请求。用户选择、组合或自由描述后，把具体结构和填写规则落实到一个模板定义中；仅在用户要求多个模板时保存多个。避免停在提示列表。用户已授权直接创建且信息充分时，采用最贴合目标的方向并继续制作；向用户发出了待选问题时，先完成不依赖选择的目录查询与输入梳理，收到选择后再落实对应结构。

## 定义可重复填写的结构

依据选择设置稳定的内容区域、布局、阅读顺序与交互，标明必填材料和可选条件。先查组件目录并评估组合，需要新组件时进入 [create-component](../../create-component/SKILL.md)。组合已有模板时按 `guide({topic:"templates"})` 使用 composition，并固定依赖。

用 contentGuide 表达每个区域怎么填、材料缺失如何展示、什么情况下删减可选区域。将应用提示存入 examples 的 `request`，名称存入 `name`，操作顺序存入 `steps`；完整形状从所选模板的 examples/source 获取。scenarios 描述使用情境，related 记录组件或子模板用途。使用现有字段保存提示，不增加未经运行时支持的 prompt 字段或变量绑定语法。

按本技能的[模板结构与填写材料](../SKILL.md#模板结构与填写材料)建立 document。新建定义使用版本 3 的 Page/Board 容器、layout 和 surfaceViews，按 `guide({topic:"containers"})` 构造；基于已有模板修改时先核对其实际模型。内容写填写说明，图表或组件使用符合 schema 的空状态。无法以空数据表达的部分先采用文本输入说明，收到真实材料后再完善。模板中的说明应提示用户填什么，不预设每个项目都成立的事实或结论。

## 保存、应用与修改

先保存模板定义，再应用到新页面，执行所选提示，用用户材料填写。通过预览展示一份使用后的结果，让用户可以具体反馈“风险放前面”“负责人要必填”“可以删除复盘区块”等。缺少真实材料时展示填写提示与有效空状态；演示数据按本技能的统一约定处理，并说明实际内容验证尚未完成。

用户修改可复用结构时，读取最新预览页及手动修改，把适用于下次的调整写回模板定义，用新版本重新应用，检查必填/可选内容、组件依赖、主要操作与导出。用户仅修改本次内容时保留实例编辑；复用验证使用新的应用页面，避免覆盖用户正在编辑的页面。

最终交付保存后的模板引用、应用预览和与实际模板一致的使用提示。使用提示可包含“我会提供哪些材料”“按哪个顺序组织”“缺项如何处理”，由 Agent 读取 contentGuide 并生成页面。后续材料变化或反馈继续迭代该模板。
