# 直接创建模板文件夹

从重复出现的读者任务、每次都要判断的事项、每次材料的来源与形状确定模板。结构未明确时给少量有实质区别的方向；已明确时直接制作。用户选择充分明确后持续完成包和真实应用验证。

按 [create-template](../SKILL.md) 创建 README.md、guides/ 和可选 components/。README 的 JSON frontmatter 是可解析的元信息（schemaVersion 3）；scenarios 写用户会怎样提出这类请求；正文是概览，不是指南目录。四阶段必须声明，确实没有额外要求的阶段设为 null，继承系统指南。

写每份指南时先列这个阶段在这类内容上要做的判断，再为每个判断写看什么、怎样决定、为什么：

- intent：深层需求的线索与重心移动；从材料本身判断读者起点；误解来源；目标怎样从主张推出。
- material：材料各部分提供什么与陷阱；记录字段；分类或核对依据；例子、术语、图像；缺口。通用场景可为 null。
- logic：从任务与贡献结构推主干；按类型选起点形态；组织原则及理由；可选环节的加入条件；第二级该问的问题；先备、通过、停止条件；两个以上结果不同的示例主干。
- design：整体布局怎样定；"必须看出什么 → 表达 → 交互 → 静态与窄屏"推导表；组件决策顺序；参考组件清单与内置替代；每幕要求；示例幕。

写完后逐条自查：规则是否都能用在没见过的材料上；具体结构是否只出现在示例里并已标注；清单是否写了条件；有没有实例名、具体数字、时间预算、必选组件。

组件库使用现有的 source/schema/documentation 合同，本地名字由 README 声明，注册器生成隔离的实际 ID 并固定版本。没有自定义组件就留空；design 指南仍给出内置替代。

用 template_save 的 portable bundle 保存，新阶段或包内容发布新模板版本，组件代码变化单独升级组件版本。调用 template_context 获取真实引用与组件索引，按阶段 template_guide，用一份真实材料走完四个阶段再 template_apply 制作实例；检查真实内容、主要交互、静态方式与完整交付。只有验证页填写完成，才说明已验证对应材料的使用。指导信息和页实例分别维护：改变方法更新包，改变本次数据更新实例。
