# 直接创建模板文件夹

从重复的读者任务、每次材料、固定主干和可选环节确定模板。结构未明确时给少量有实质区别的方向；已明确时直接制作。用户选择充分明确后持续完成包和真实应用验证。

按 [create-template](../SKILL.md) 创建 README.md、guides/ 和可选 components/。README 的 JSON frontmatter 是可解析的元信息（schemaVersion 3）；正文保持简短，详细方法放在所属阶段。四阶段必须声明，确实没有额外要求的阶段设为 null，继承系统指南。Markdown 阶段文件夹以 README.md 为主入口，细节子文件按需读取。

- intent：这类内容的默认读者、他们常见的深层需求、容易误解的点、可检验的目标与任务清单、材料入口与环境默认。
- material：需要哪些原始信息、从哪里取、记录哪些字段、怎样核对与分类、常见缺口怎样处理；通用场景可为 null。
- logic：主干表（环节、主题、读者读完知道什么）、可选环节与加入条件、每个环节要讲清的内容、先备关系、组织原则。
- design：整体布局与文字模式；每幕表（画面起点、交互、组件局部名与内置替代）；每幕要求（首屏、对象身份、口径、静态与窄屏）。

阶段说明不复制整份系统基线，也不为填满目录增加无意义内容。

组件库使用现有的 source/schema/documentation 合同，本地名字由 README 声明，注册器生成隔离的实际 ID 并固定版本。没有自定义组件就留空；design 指南仍给出内置替代，使没有组件库的使用者能实现同样的画面。

用 template_save 的 portable bundle 保存，新阶段或包内容发布新模板版本，组件代码变化单独升级组件版本。调用 template_context 获取真实引用与组件索引，按阶段 template_guide，用一份真实材料走完四个阶段再 template_apply 制作实例。检查真实内容、主要交互、静态方式与完整交付。只有验证页填写完成，才说明已验证对应材料的使用。

指导信息和页实例分别维护：改变复用方法更新包，改变本次数据更新实例。用户提出的反馈融入新内容，避免在模板正文逐条回应修改历史。
