# 直接创建模板文件夹

从重复出现的读者任务、每次都要判断的事项、每次材料的来源与形状确定模板。结构未明确时给少量有实质区别的方向；已明确时直接制作。用户选择充分明确后持续完成包和真实应用验证。

按 [create-template](../SKILL.md) 创建 README.md、guides/ 和可选 components/。README 的 JSON frontmatter 是可解析的元信息（schemaVersion 4），guides 按阅读顺序列出指南文件；scenarios 写用户会怎样提出这类请求；正文是概览，不是指南目录。

写指南时先列这类内容在制作流程上要做的特别判断，再为每个判断写看什么、怎样决定、为什么。按 create-template 的“指南写什么”组织：判断读者、处理材料、组织讲解、画面与组件，以及可选的评审要点；没有特别做法的部分不写。组织讲解要附两个以上结果不同的示例主干，画面与组件要附至少两幕不同任务的示例幕。

写完后逐条自查：规则是否都能用在没见过的材料上；具体结构是否只出现在示例里并已标注；清单是否写了条件；有没有实例名、具体数字、时间预算、必选组件。

组件库使用现有的 source/schema/documentation 合同，本地名字由 README 声明，注册器生成隔离的实际 ID 并固定版本。没有自定义组件就留空；画面与组件的指南仍给出内置替代。

用 template_save 的 portable bundle 保存，指南或包内容变化发布新模板版本，组件代码变化单独升级组件版本。调用 template_context 获取真实引用、全部指南与组件索引，用一份真实材料按 show-document 的流程走完，再 template_apply 制作实例；检查真实内容、主要交互、静态方式与完整交付。只有验证页填写完成，才说明已验证对应材料的使用。指导信息和页实例分别维护：改变方法更新包，改变本次数据更新实例。
