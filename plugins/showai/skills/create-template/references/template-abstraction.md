# 从成熟实例提炼模板

先读取完整原 Page、hash/revision 与精确组件引用，并取得它的读者简报、呈现规划与设计稿（没有记录时从页面反推并标明）。识别在不同材料中仍成立的部分：读者与深层需求、材料采集与核对方式、主干与可选环节、每幕的画面模式、交互与检查。本次发现、日期、数值、贯穿例子和素材来源属于实例，不进入模板。不要仅复制截图或章节名称。

按 [create-template](../SKILL.md) 的文件夹格式提炼。README 记录名称、用途、版本、场景和阶段/组件入口，短正文说明这类内容的共同做法。guides/ 按四阶段分别保存：intent 写默认读者、深层需求类型、常见误解与可检验目标；material 写采集清单、数字记录字段、论断分类；logic 写主干表（环节、主题、读者读完知道什么）、可选环节与每环节要讲清的内容；design 写每幕表（画面起点、交互、组件与内置替代）、整体布局与文字模式。系统已经规定的共性直接继承。

抽取组件前检查是否需要复用代码。仅改输入/布局够用时沿用公共能力；确实有专题图形或交互需要才放入 components/。该库使用本地 ID、真实 schema、默认空状态和版本化使用/开发说明；注册器生成实际引用，不能写死另一个项目的路径或指纹。只属于某一篇材料的机制组件不进模板，在 design 指南中说明何时按 create-component 新建。

保留原实例。新包保存后，以另一份材料走完四个阶段并应用，检查密度、概念展开、交互和静态方式。验证发现某幕只适合原实例时，缩小适用场景、改为可选或改成实例内容。材料不足时交付可用结构和未验证范围，避免编造实测结论。

后续修改发布新模板版本；组件代码改变也升级组件版本。旧的六阶段包仍可读取或显式维护，新建抽象采用四阶段。
