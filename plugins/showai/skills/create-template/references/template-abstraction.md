# 从成熟页面抽象模板

用户给出现有页面或希望先看效果时，通过实例确定结构，再表达下一次应填写什么，以及哪些结构值得重复使用。

没有源页面时，按 show-document 用用户材料创建一页，展示效果并迭代布局、信息层次与主要交互。已经授权创建模板时，页面达到需求后继续提炼与验证。已有成熟页面可直接开始；结构仍待明确时先完成有用的页面预览，围绕具体效果收集反馈。

提炼前查询 `guide({topic:"template-extraction"})`，读取当前页面、hash 与 revision；有此前读取版本时查询差异，纳入用户的手动修改。查询相似模板的 guide/examples，判断哪些结构适合重复使用、哪些应留在当前实例。

识别稳定部分：叙事顺序、信息层次、交互的用途、组件布局与关系。将本次的人名、日期、指标、结论和项目状态换成填写提示；数组型数据使用符合 schema 的空状态，不支持空数据的部分使用文本填写说明。演示数据按本技能的[模板结构与填写材料](../SKILL.md#模板结构与填写材料)处理。标题与小节名称保留用途，不写入只有当前实例成立的结论。

contentGuide 按内容角色说明必需材料、证据、组织要求与可选条件；related 记录组件或子模板的用途；examples 用命名的自然语言使用提示与操作顺序说明怎么应用。使用提示应对应实际结构，例如“用这份模板，基于我提供的两种方案和来源，按成本、适用条件和风险比较，缺项标为待补充”。复用已有组件时保留精确引用，定制组件源码仍留在可编辑包中。组合已有模板时使用 composition 并让运行时 固定依赖指纹。按源页面的实际模型保留布局和视图：版本 3 使用 layout 与 surfaceViews，旧版本 2 白板使用 layout 与 views；转换模型时读取 `guide({topic:"containers"})`，同时保留容器类型和节点关系。

当前模板模型保存文档结构与填写说明，由 Agent 根据用户材料生成新页面。不要将文本提示描述为已实现的参数绑定或自动填充系统。template_save只传pageId时偏向保存快照；完整抽象使用处理过的input.document定义。

验证时用另一组用户材料创建新页面：实例名称和数值不应泄漏；可选区块能删减；图表与组件数据符合 schema；导出仍可打开。缺少另一组材料时先检查结构、空状态和依赖，说明跨材料验证待补齐。保留源页面，模板和验证页面分别保存。

用户对验证结果提出结构反馈时，更新模板定义并保存新版本，再应用检查；原实例继续保留。交付模板引用、使用提示、成熟实例与验证结果，便于下次提供材料直接应用。
