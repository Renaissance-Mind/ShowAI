# 规划呈现

从用户材料与当前对话确定读者需要理解、判断或完成什么。区分明确要求、上下文支持的假设和未知条件；只询问会改变结论、范围或交付方式的缺项。用户只要简单回答时直接回答，规划按任务规模压缩，不自动创建页面。

用 [呈现工作约定](references/presentation-contract.md) 建立简洁任务简报：读者、认知起点、目标结果、范围、材料、环境与通过条件。深层需求是待验证假设；发现有影响的误解时，用定义或具体例子澄清，再回到原问题。

按 [理解规划](references/understanding-plan.md) 组织材料和多级路径。先备概念、证据与条件形成关系；主阅读路径按读者起点安排。各分支按需要展开，直到读者能够完成对应任务。复杂关系的结构、讲解顺序和屏幕展开分别决定。

已有材料足够时省去另行收集；保留来源、支持范围和缺口检查。领域采集方法按需采用。时间范围报告区分事件日期、发表日期和检索截止日；无法核实的部分保留缺项。生成示意、设计建议和推断应有明确性质，不能作为实测证据。

## 交付与接续

交付任务简报、多级理解规划、重要证据缺口及每个主节点的通过条件。重点节点写完整，其余保持足够简洁；不强制统一层数或把所有问题展开到底。

- 用户只要规划：形成可审阅的规划；要求正式方案页面时由 [show-document](../show-document/SKILL.md) 保存与展示。
- 用户要视觉或交互设计：将规划交给 [design-presentation](../design-presentation/SKILL.md)。
- 用户要完整作品：继续 [show-document](../show-document/SKILL.md) 的制作、验证和交付。
- 用户反馈看不懂：读取当前原作品和反馈，定位障碍后重组相关内容，保持原作品连贯。

已有规划和材料足够时直接接续，不重新走完前面的环节。设计记录使用现有内容与工作材料，不把示例字段当作 MCP 新参数。
