# 呈现工作约定

围绕读者的实际任务组织内容。复杂任务依次形成任务简报、证据底稿、理解规划、视觉分镜、源页面和质量记录；简单任务可以把这些判断合并。已完成且仍有效的产物直接复用，阶段交接不要求用户逐次确认。

## 任务简报

| 项目           | 需要明确的内容                                       |
| -------------- | ---------------------------------------------------- |
| 读者与认知起点 | 谁阅读；已知什么；有影响的疑似误解；哪些仍不确定     |
| 目标结果       | 读者看完后能解释、判断或完成什么；用什么任务检验     |
| 范围与材料     | 必须覆盖、可省略、来源、缺口；推断的深层需求标为假设 |
| 环境           | 设备、实际视口、阅读时间、交互能力、静态或离线交付   |
| 约束           | 用户指定的格式、素材、模板、入口与保存归属           |

没有特殊要求时，以电脑全屏交互阅读为设计参考；实际宿主可能是窄面板，交付前核对视口。不要把显示器分辨率直接当作 CSS 视口，也不要把长文统一压成固定比例画布。

## 阶段交接

| 阶段     | 可审阅产物                       | 进入下一步的条件                             |
| -------- | -------------------------------- | -------------------------------------------- |
| 理解意图 | 任务简报                         | 目标可检验，影响结果的未知条件已处理或标明   |
| 处理材料 | 主张、来源、条件与缺口的对应     | 关键主张有依据，结论范围不超过材料           |
| 规划理解 | 多级节点与先备关系               | 主线连贯，必要概念有落点，各分支深度适合读者 |
| 设计表达 | 对象、关系、布局、文字与交互分镜 | 表达服务理解任务，素材与现有能力可支撑       |
| 制作页面 | 本次内容、布局、素材与精确依赖   | 真实内容与设计一致，缺项和错误可识别         |
| 评审交付 | 问题、修订与验证范围             | 主要任务可完成；保存、导出和显示各有对应证据 |

发现问题时回到负责它的阶段。错读数据要修正材料或推断，缺少先备概念要调整主线，标签难读要修正版式，选择后无反馈要修正状态设计。

## 记录与权限

复杂任务保留简洁的目标、证据、关键设计选择和未覆盖项，便于续改。用户只要求设计时交付规划与设计稿；用户要求成品时继续完成成品。最终正文保留读者需要的方法和限制，制作过程记录放在相应工作材料中。

这些是设计记录的内容约定，不是新的 API 或自动参数绑定系统。简单问答、用法和仅在对话中讨论提纲时直接回答。用户要求完整规划、设计稿或报告等可审阅成果时，默认按已核实的项目归属保存正式 Page 并展示；用户明确只在对话中讨论、只要文件或不入库时，遵循指定方式。设计方案的保存属于文档交付；“先设计、不实现”限制的是后续应用或组件实现，不自动改变内容保存归属。

当前连接与项目已核实就继续操作。首次接入、换项目或归属不明时，使用 [use-showai](../../use-showai/SKILL.md)。截图只证明相应视图；交互检查与真实读者试读分别记录，遵循宿主的电脑操控规则。
