# 表达与分镜

## 依据理解任务选择表达

| 读者任务           | 主要表达                       | 说明与交互                           |
| ------------------ | ------------------------------ | ------------------------------------ |
| 认识对象与组成     | 原图、截图、剖面或标注示意     | 定义关键对象，选择局部时就近解释     |
| 理解步骤与状态变化 | 流程、连续分镜、前后状态       | 说明触发条件，保持对象身份           |
| 理解机制           | 输入—作用—结果关系             | 说明依据、假设和适用边界             |
| 比较与取舍         | 对照表、同尺度小多图、决策路径 | 使用共同口径，缺项可识别，建议带条件 |
| 趋势、分布与异常   | 与数据语义匹配的图表           | 单位、样本、日期、原始值及来源       |
| 完成操作与排错     | 真实界面标注、步骤与分支       | 动作、预期反馈和恢复方式             |
| 探索与系统理解     | 总览与可定位局部               | 放大、筛选、详情及返回总览           |
| 核对论证或精确规定 | 有层次的正文、公式和原文       | 突出条件，图文相邻，来源可定位       |

每张主图应明确读者要从中发现什么。图形的方向、空间、连接和尺度承担语义；文字补充定义、条件与推理。装饰不能制造未经证据支持的因果、比例或排名。颜色与文字、形状或线型共同表达状态；同类语义保持一致。

## 每一段设计稿

记录理解任务与核心信息、对象与素材来源、视觉编码、布局与阅读顺序、准确文案及强调、交互状态、静态替代、候选资源、能力缺口和通过条件。可写成紧凑表格或类似图像生成提示的具体段落。

例如：暖白底，标题直述“模板如何组织内容”。中央横向呈现本次材料、模板结构和本次页面，箭头表示填入与组装。橙色标出适用条件及其进入最终页面的位置。图注位于当前焦点下方，解释该条件影响的结论。完整填写约定可原位展开，主要条件初始可见。

## 环境与排版

默认以电脑全屏交互阅读为主要场景，可用 1440×900 CSS 像素作为设计参考；实际宿主视口决定布局。示意图或演示画面可用 16:9，长文自然纵向排布。窄视口重排图文和导航，必要的二维表图提供明确的滚动与总览方式。

按阅读场景选择正文基准与最小字号。18–20 px 可作为桌面正文起点，实际图注和标签按渲染尺寸检查；空间不足时改结构或拆分，避免依赖极小字号。固定字体体系，使用留白、对齐、间距和语义分组；标题直述主题，重点的样式与含义一致。沿用 show-document 的排版规则。

必要图形提供文字替代，颜色不单独传递信息；检查文字和状态对比、键盘焦点、放大与重排。这些设计检查不等于宣称已通过完整无障碍合规。

## 交互分镜

明确初始状态、触发动作、状态变化、可见反馈、恢复方式、键盘和窄屏行为。需要联动时通过稳定对象身份说明图形、正文和数据如何对应，并核实当前组件实际支持的接口。

阅读中的选择、筛选、缩放和临时参数属于阅读状态；更改事实或持久默认值需要正式保存。空数据、错误、加载与缺少来源都显示真实状态。重要条件不能只放在悬停说明里。

静态交付保留主线、重要条件和来源。逐步交互转为关键状态的连续分镜；计算探索保留公式、范围、选定条件与结果。无需枚举无限状态，但必须支持原定的静态阅读任务。导出 HTML 可交互，不自动等于纸面或图片版本已经完整。

## 图像生成

先确定对象、关系、标签、构图和不应改变的事实，再生成候选。检查文字、箭头、数量、比例暗示与遮挡；出现自动补出的数据或主张时修订。正文、精确数据和要交互的对象尽量保持原生可编辑。保留采用的图片、提示词及必要修改记录，标明生成示意与真实素材。

## 保存分镜

在理解规划的 scenes 中，逐段记录 id、nodes（理解节点 id）、form（图形表达类型）、composition（对象、相对位置、箭头或尺度、准确标签、阅读顺序与文字落点）、visualReason（为什么这种表达能支持当前任务）、static、narrow、check。有交互时增加 interaction={trigger,change,reset}；可另记录素材来源、候选资源和缺口。

这些字段应让另一位制作者能画出或实现同一画面。“文字＋关系图”“白底简洁”等不能单独成为 composition。正文承担精确论证时说明必要性；适合空间、变化或比较表达的关系，优先通过图形组织。首屏包含核心回答、必要范围和可理解的视觉总览，背景按需移到对应位置。不要先写完整长文再给各章附一张概括图。

从读者要观察的差异反推画面。机制比较应在稳定位置显示对象、变化与继承，时间调研应让事件按主题和日期定位。主视觉无法说明具体关系时，调整规划或表达；几个抽象名词放进框中仍可能缺少机制解释。

在目录查找适合的真实能力：mechanism-steps 保持对象身份并逐步显示状态与作用关系；evidence-explorer 连接总览、条件、来源和共同维度比较。按任务选用，可与原生图表、图像、容器及正文组合。缩放、折叠和链接解决访问问题；当任务是理解变化或比较条件时，交互应让相关对象或结果随选择产生可见变化。静态阅读仍保留完整主线。

## 用真实内容检查分镜的密度

在目标视口估计标题、说明、控件和主图共同占用的空间。首屏让核心关系或总览可辨认；正文中的长定义、背景和方法放到它所解释的图形附近或后续段落。Page 标题不在正文重复。

每个主要理解任务都要有具体的表达落点。一个“证据探索＋专题正文”场景不能自动覆盖所有机制解释；逐项检查读者如何从图形或示例看出变化、因果、条件和差异。长章节按理解节点拆成图文相邻的片段，避免一两个交互区后接几大块连续正文。表格适合共同维度，时间×主题关系可用 evidence-explorer 的 timeline 布局；机制的状态变化可用 mechanism-steps。证据条目不能代替需要展开的机制。

使用原生图形或 Image Gen 制作具体概念图时，让对象和关系承担解释工作。生成图保持定义、数量和箭头准确，精确数据及可操作对象留在原生组件中。不用装饰图代替缺少的解释。
