# 模板与组件选择

模板复用阅读任务、内容顺序与填写约定，组件复用图形和交互能力。Page 保存本次事实、素材、布局和精确依赖。先选择适合内容关系的表达，再核对当前可用资源。

## 模板家族

较新运行时提供以下六类原生 Page 模板；先查当前目录，工具实际返回为准。旧运行时没有这些模板时按相同理解结构使用现有组件制作，不能声称已应用不存在的模板。

| 模板 ID             | 阅读任务             | 必需材料与组织方式                       |
| ------------------- | -------------------- | ---------------------------------------- |
| concept-explainer   | 理解概念与机制       | 具体问题、对象定义、关系依据、例子和边界 |
| decision-comparison | 依据条件比较并选择   | 共同标准、可比事实、约束、缺项和取舍     |
| evidence-report     | 判断研究证据支持什么 | 问题、范围、方法、来源、条件、发现和局限 |
| procedure-guide     | 完成操作并处理异常   | 前提、真实入口、动作、反馈、恢复         |
| progress-report     | 理解当前状态与下一步 | 截止时间、变化、依据、风险及待决策事项   |
| exploration-map     | 探索分类与关系       | 条目、属性、分类或关联、来源与检索方式   |

新建复杂作品时，实际查询 `catalog_list({kind:"template",projectId})`，读取匹配项的 guide。用户明确指定从空白开始时沿用其选择；其余请求匹配则在制作阶段用 template_apply 创建并填入本次内容，没有合适结构时记录具体缺口再从空白组装。目录查询与组件选择是不同操作，componentCatalog 不包含模板。

先核对阅读任务、材料和交付环境，再检查认知深度、信息量和组织方式，最后调整样式。局部结构可以组合。缺少必需证据时保留缺项或缩小结论，避免为填满模板制造内容。

新模板以 README 元信息与简短基础说明、guides 分阶段指南、可选 components 库和 page.json 保存可复用方法。template_context 固定本轮版本，template_guide 只读当前阶段。旧 document/composition/contentGuide 等定义保持可读；Agent 根据材料填写。没有自动变量绑定或跨组件联动的通用承诺。填写约定不是实际调研结果，成品交付前清除未完成的填写提示，真实缺项保留为明确的限制。

## 组件候选

- 对象与材料：image、gallery、video、pdf；局部热点是否可用，查具体组件。
- 概念与关系：flowchart、mindmap；项目目录有 text-diagram 时按其 guide 使用。
- 对照与证据：evidence-explorer 支持主题×时间总览、详情和共同维度比较；table、database、chart、适配数据类型的 G2 图表、references 和 bookmark。
- 补充说明：text、toggle；关键条件进入主线。
- 参数探索：playground 只支持它公开的有限计算，专题模型按各自假设使用。

使用完整的当前组件索引选择，再读取精确版本的 guide/parameters。调整实例数据和布局 → 组合已有能力 → 扩展已有组件 → 为确认的缺口创建新组件。通用、专题、内容专用分别判断，不能仅因外观相似复用写死事实的作品组件。

组合不足时，为 create-component 提供：输入与输出、视觉语义、读者操作、状态归属、空态与错误态、窄屏与静态方式及通过条件。新能力完成后回到整体作品制作。

参数类型、单位、坐标系和关系使用组件精确版本的 parameters 参考核对；它由 schema 与字段语义生成。按 parameterPath 取当前对象/关系涉及的字段，不将整个目录的参数表一次读入。缺失说明保持未知，不能仅依据字段名猜单位或默认行为。
